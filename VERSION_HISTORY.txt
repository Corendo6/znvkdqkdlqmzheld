쿠팡 관리 프로그램 버전 변경 기록
현재 버전: 0.4.13

이후 버전도 이 파일 하나에 누적합니다. 최신 변경 내용이 위에 있습니다.
실행·사용 안내는 README.txt, API 초기 설정 안내는 API_SETUP_KR.txt를 참고하세요.
이전 기록은 당시 작성된 원문입니다. 현재 동작은 최신 버전 설명을 따릅니다.

============================================================
v0.4.13 · 일일 매출 API 판매량 통일 / 쿠팡 사이즈 붙여넣기
============================================================
1. 어제·7일·30일 판매량을 판매자·옵션별 일일 주문 API 판매수량으로 계산합니다.
   - 한국시간 어제까지 합산하며, 재고 API의 30일 수량과 수동·Excel 자료를 섞지 않습니다.
   - 수집 완료 날짜를 기록해 0건과 미조회를 구분합니다. 불완전한 기간은 —로 표시합니다.
   - 재조회 중복 합산 방지 및 실패 시 이전 자료 유지 동작을 유지합니다.
2. API 매출 조회 기본값을 최근 30일로 변경하고 최근 30일 버튼을 추가했습니다.
   - 매출 저장 직후 재고 화면도 갱신합니다. 매출 마지막 조회 시각과 오류를 표시합니다.
3. 판매량 정렬·품절 상품 표시·소진 예상·입고권장을 동일한 30일 매출 수량에 맞췄습니다.
4. 그로스 마진 수정창에서 쿠팡의 사이즈 설명을 붙여 넣어 등급을 선택할 수 있습니다.
   - 예: 극소형 - 182*311*49(mm), 455g. 치수·무게는 별도로 저장하지 않습니다.
5. 기존 성공한 매출 조회의 마지막 기간을 복원하며 사용자 데이터는 보존합니다.
6. 재고 화면에서 프로그램 종료 시 타이머를 중복 정리하던 오류를 수정했습니다.

============================================================
v0.4.12 · 그로스 마진 더블클릭 수정 / 메모리 상품 표시 제외
============================================================
1. 그로스 마진의 더블클릭 동작을 상품 링크 열기에서 수정창 열기로 변경했습니다.
   - 실제 클릭한 옵션 행의 원가·사이즈형을 함께 수정합니다.
   - Enter·선택 수정·우클릭 수정도 같은 창을 사용합니다.
   - 헤더·빈 공간의 더블클릭으로 이전 선택 행이 열리지 않도록 했습니다.
   - 쿠팡 링크는 우클릭 메뉴에서 명시적으로 선택할 때만 엽니다.
2. 원가·사이즈형을 한 번에 저장하고 같은 모델 옵션들의 마진을 다시 계산합니다.
   - 현재 판매가와 상품 DB 가격은 수정하지 않습니다.
   - 잘못된 금액·NaN·무한대·0·음수는 저장하지 않습니다.
   - 원가 빈칸·사이즈 미지정은 기존 값을 유지하며, 취소·Esc는 저장하지 않습니다.
   - 저장 후 검색·미확인 필터와 가능한 경우 선택 행을 유지합니다.
3. 그로스 마진 일괄 현황에 누락된 멀티탭 전용 표시 조건을 적용했습니다.
   - 기본 설정에서 C50 등 샌디스크 메모리를 목록·검색·요약 집계에서 제외합니다.
   - 기존 단건 계산기와 같은 표시 범위를 따릅니다.
   - USB 충전 멀티탭, 같은 모델·등록상품에 연결된 이름 없는 옵션은 유지합니다.
   - 기존 상품·매출·원가 데이터는 삭제하지 않습니다.
4. 검증
   - 기존 재고·매출·마진 자동 테스트 35개 통과.
   - 실제 Tk 더블클릭·Enter·선택 수정, 취소·입력 검증·저장·동일 모델 반영,
     검색 유지·미확인 필터·재실행 저장 유지·1180×720 수정창을 확인했습니다.
   - C50 제외·USB 멀티탭 유지·설정 켜기/끄기의 표시 범위 일치를 확인했습니다.
   - 수정 중 API 호출 0회·브라우저 열기 0회·저장 판매가 동일을 확인했습니다.
   - 로켓그로스 재고 화면의 현재 판매가 마진·상세·CSV·검색 회귀 검증 통과.
   - Windows EXE 빌드·실행 및 실제 계정 API 호출은 확인하지 못했습니다.
5. 마스터 데이터 통합, API 실행 위치 한 곳, 현재 판매가 기준 마진을 유지합니다.
   버전 변경 기록은 이 TXT 하나에 누적합니다.

   - 요금 탭에서 검색 적용 시 모델·옵션 매핑 탭으로 이동합니다.
   - 취소하면 현재 탭을 유지하고, 하위 탭 전환 시 검색어도 유지합니다.
   - 모델 목록과 미매칭 목록의 높이를 구분선으로 조절할 수 있습니다.

   - Windows EXE 빌드·실행 및 실제 계정 API 호출은 확인하지 못했습니다.
5. API 실행 위치 한 곳, 현재 판매가 기준 마진, 상품 관리 로켓그로스 숨김을 유지합니다.

v0.4.10 · 현재 판매가 기준 마진 표시로 정리
============================================================
1. v0.4.9에 불필요하게 추가한 가정 판매가 입력·가격 비교 기능을 제거했습니다.
2. 로켓그로스의 '현재 판매가' 옆에 개당 예상 마진·마진율을 바로 표시합니다.
   - 상품 관리에 저장된 현재 판매가와 원가·수수료·물류비로 자동 계산합니다.
   - 상품정보 갱신으로 판매가가 변경되면 해당 가격으로 다시 계산합니다.
   - 현재 판매가가 없으면 과거 엑셀 가격으로 대신하지 않고 미확인으로 표시합니다.
3. 판매가·마진 클릭 또는 Ctrl+Enter는 '현재 판매가 마진 상세'를 엽니다.
   - 현재 판매가·원가·수수료·입출고비·배송비·마진·마진율만 표시합니다.
   - 가격 입력칸이 없는 읽기 전용 창입니다.
4. 검증: 자동 테스트 35개 및 실제 Tk 화면 검증 통과.
   - 현재 판매가 17,200원 → 마진 -3,311원 표시 확인.
   - 테스트 DB의 판매가를 21,000원으로 갱신 후 마진 163원 자동 재계산 확인.
   - 마진 상세에 입력칸 없음, 조회 전후 DB 동일, UI API 요청 0회 확인.
   - F5·필터·페이지·CSV·입력 누락·1180×720 화면 검증 통과.
   - Windows EXE 빌드·실행과 실제 계정 API 호출은 확인하지 못했습니다.
5. F5 검색, 로켓그로스 숨김 설정, 자체 입고권장 계산, API 실행 위치를 유지합니다.

v0.4.9 · F5 검색 정리 / 로켓그로스 개당 마진 · 판매가 비교
============================================================
1. 상품 관리·로켓그로스의 상시 검색 입력칸을 제거했습니다.
   - F5 검색을 유지하고 검색 버튼·검색어 표시·검색 해제를 제공합니다.
   - 배송·판매상태·재고상태 필터는 검색 후에도 유지합니다.
2. 로켓그로스 재고 화면을 간결하게 정리했습니다.
   - 행 높이 176 → 132, 얇은 셀 구분선, 금액 오른쪽 정렬.
   - 반복 배송 배지·설명과 누적보관비 빈칸을 없애고 핵심 정보에 집중합니다.
   - 쿠폰가·지도가 등 보조 정보는 가격 비교 창에서 확인합니다.
   - 최소 창 크기에서도 페이지 이동·선택 건수·마진 칸을 유지합니다.
3. 현재 판매가 옆에 개당 예상 마진과 마진율을 표시합니다.
   - 기존 그로스 마진과 동일한 원가·수수료·물류비 계산을 공통 모듈로 연결합니다.
   - 원가를 공급가로 추정하지 않으며 입력 누락은 —와 미확인 사유로 표시합니다.
   - 재고 화면의 현재 판매가는 저장된 상품 가격만 사용합니다.
   - 그로스 마진의 기존 엑셀 가격 fallback은 해당 화면에서만 유지합니다.
4. 판매가·마진 클릭 또는 Ctrl+Enter로 가격 비교 창을 엽니다.
   - 가정 판매가 입력 즉시 개당 마진·마진율·수수료·입출고·배송비를 비교합니다.
   - 가격 구간을 넘으면 해당 구간의 물류비를 적용합니다.
   - 가격 입력은 메모리에서만 계산하며 상품 DB 변경·쿠팡 API/PUT 요청은 없습니다.
5. 적자 상품·마진 미확인 필터, 마진 낮은 순 정렬을 추가했습니다.
   - CSV 내보내기에 원가·물류비·마진·마진율·미확인 사유를 추가합니다.
   - 재고·마진의 DB 조회를 일괄 처리하며 화면에 보이는 행만 그립니다.
6. 검증
   - 기존 재고·매출 테스트 25개, 마진 계산 테스트 10개 통과.
   - 실제 Tk 화면: F5·필터 유지·검색 해제, 가격 비교·요금 구간 변경·잘못된 입력,
     원가 미확인·음수 마진 CSV·페이지·선택·1180×720 화면을 확인했습니다.
   - 가격 비교 전후 DB 동일, 화면 조작 API 호출 0회 확인.
   - 상품 관리 숨김·재실행·두 보기·상세·복사·접기·2,000개 옵션 검증 통과.
   - Windows EXE 빌드·실행과 실제 계정 API 호출은 확인하지 못했습니다.
7. 로켓그로스 숨김 옵션, 자체 입고권장 계산, API 실행 위치 한 곳을 유지합니다.

CoupangManager v0.4.1 - 그로스 마진 자동화

목표
- Excel에서 하던 그로스 마진 계산을 단건 버튼 작업이 아니라 프로그램 내부 자동 데이터 흐름으로 변경.

데이터 흐름
1) 상품 API 동기화 -> 로켓그로스 옵션별 현재 판매가 저장
2) vendorItemId/옵션 -> 모델명 매핑
3) 기존 그로스 마진표 또는 모델 마스터 -> 원가 연결
4) 모델별 풀필먼트 사이즈형 -> 현재 fulfillment_rates에서 판매가 구간에 맞는 입출고비/운송비 자동 선택
5) 수수료/정산가/물류비(VAT)/마진/마진율 자동 계산
6) 그로스 마진 탭에서 전 로켓그로스 옵션 일괄 표시

화면
- 사이드바 '마진 계산' -> '그로스 마진'
- 기본 화면은 '일괄 현황'
- 로켓 옵션 / 자동 계산 / 미확인 / 적자 / 평균 마진율 요약
- 모델명, 옵션명, 판매상태, API 판매가, 원가, 사이즈형, 입출고비, 운송비, 물류비, 정산가, 마진, 마진율, 옵션ID 표시
- 미확인 데이터는 노란색, 적자 품목은 붉은색 표시
- 검색 / 미확인만 필터
- 행 더블클릭 또는 우클릭으로 쿠팡 상품 열기

사이즈형
- 기존 마진표의 정상 사이즈형을 자동 이관
- 기존 #VALUE! 행도 과거 입출고비+운송비 조합이 현재/정규 요금표에서 정확히 한 사이즈에만 매칭되면 자동 복구
- 애매한 모델은 임의 추정하지 않음
- '선택 사이즈형 지정'으로 모델별 1회 저장 -> 이후 판매가가 변해도 해당 판매가 구간의 현재 요금이 자동 적용

원가
- 기존 그로스 마진표에 원가가 있으면 그 값을 우선 유지
- 신규 모델은 모델 마스터 공급가(VAT 포함) / 1.1을 fallback으로 사용

단건 계산기
- 기존 계산 기능은 '단건 계산기' 탭으로 유지
- 기존 품목을 불러올 때 로켓그로스 판매가는 가능하면 현재 상품 API 값을 우선 사용

API 동기화 연동
- 상품 API 동기화가 끝났을 때 그로스 마진 화면이 열려 있으면 즉시 다시 계산/표시

핵심: 모델 마스터 + 쿠팡 일일매출 옵션ID 자동 매칭

1. 모델 마스터 추가
- 좌측 메뉴에 '모델 마스터' 추가
- 사용자가 제공한 ★(주)씨에스1 현대멀티탭 9월 11일.xlsx를 기준으로 706개 모델 기본 데이터 포함
- 모델명 / 분류 / 품명 / 색상 / 포장타입 / 입수량 / 공급가 / 쿠팡 등록가 / 원본 시트 관리
- 기존 DB에서도 model_master가 비어 있으면 v0.3.5 첫 실행 시 기본 모델 마스터를 자동 생성
- 최신 현대 단가표가 나오면 '현대 단가표 가져오기'로 다시 갱신 가능

2. 옵션 ID → 모델명 매핑 DB
- option_model_map 테이블 추가
- 기존 상품관리 products의 옵션 ID(vendorItemId)와 모델명을 자동으로 기준 매핑으로 생성
- 수동 지정한 매핑은 상품 동기화/재생성으로 덮어쓰지 않음
- 신규 옵션이 생겨도 상품관리 DB에 모델명이 있으면 자동으로 매핑에 반영

3. 쿠팡 일일매출 원본 Excel 직접 가져오기
- 일일 매출 화면에 '쿠팡 일일매출 Excel' 버튼 추가
- 쿠팡 SELLER_INSIGHTS_VENDOR_ITEM_METRICS 형식의 실제 컬럼을 사용
  옵션 ID / 옵션명 / 상품명 / 등록상품ID / 판매방식 / 매출(원) / 주문 / 판매량
- 가져오기 전에 매출 기준일을 사용자가 직접 확인/입력
- 0매출/0주문/0판매량 행은 저장하지 않음
- 옵션 ID를 기준으로 모델명을 자동 입력
- 같은 날짜 + 옵션 ID + 판매방식 재가져오기는 중복 추가 대신 갱신

4. 미매칭 옵션 자동 보관
- 모델명을 찾지 못한 옵션 ID는 버리지 않고 '미매칭 옵션'에 저장
- 해당 매출도 sales_pending에 대기 상태로 보관
- 모델 마스터 화면에서 옵션을 선택하고 모델명을 한 번 지정하면
  옵션ID → 모델 매핑을 영구 저장하고 대기 매출을 일일매출로 자동 이동
- 같은 옵션 ID는 다음 파일부터 자동 매칭

5. 일일 매출 화면 개선
- '옵션명/모델' 표기를 '모델명'으로 정리
- 옵션 ID, 쿠팡 옵션명을 별도 열로 표시
- 모델명/옵션ID/옵션명 통합 검색
- CSV 내보내기에도 옵션 ID와 쿠팡 옵션명 포함

6. DB 마이그레이션
- model_master / option_model_map / unmatched_options / sales_pending 테이블 추가
- sales에 option_id / option_name / product_name / registered_product_id / source 컬럼 추가
- 기존 상품/입고/매출 데이터는 삭제하지 않음

테스트
- Python 문법 검사 통과
- 기존 starter.db → v0.3.5 마이그레이션 확인
- 기본 모델 마스터 706개 자동 생성 확인
- 기존 상품 옵션ID 매핑 411개 생성 확인
- 실제 현대 단가표 구조 파싱 검증
- 실제 2026-10-02 쿠팡 일일매출 샘플 기준: 매출 발생 행 42개 중 34개 자동매칭, 8개 미매칭 대기 처리 확인
- 미매칭 옵션 수동 지정 후 대기 매출 자동 반영 확인

참고
- 현재 상품관리 기준 모델명 중 현대 단가표와 정확히 일치하지 않는 값은 HM16-415 1개이며,
  제공된 현대 단가표에는 HM16-415cm으로 표기되어 있습니다.
- 자동 추측으로 바꾸지 않고 원본 표기를 보존합니다.

CoupangManager v0.2.4 수정사항

1. 모델명 API 매핑 수정
   - 기존 버전에서 modelNo/externalVendorSku가 비어 있을 때 sellerProductName(등록상품명)을 모델명으로 넣던 오류 수정
   - 이제 모델명은 다음 우선순위만 사용
     1) modelNo (쿠팡 모델번호)
     2) externalVendorSku (판매자상품코드)
   - 둘 다 없으면 모델명은 빈 값으로 유지하며 등록상품명을 대신 넣지 않음

2. 기존 잘못된 자동등록 데이터 자동 교정
   - '쿠팡 API 자동등록' 행 중 모델명이 상품명/노출명과 동일하게 잘못 들어간 행은 다음 동기화 시 자동 정리
   - API에서 실제 modelNo/externalVendorSku가 내려오면 실제 코드로 교체
   - 둘 다 없으면 모델명은 빈 값으로 교정
   - 사용자가 직접 입력한 기존 엑셀/수동 상품의 모델명은 자동으로 지우지 않음

3. 상세조회 실패 임시행 수정
   - 상세조회 실패 시 목록의 등록상품명을 모델명으로 넣지 않음
   - 모델명은 빈 값으로 두고 note에 '모델명 미확인' 표시

4. 기존 기능 유지
   - Marketplace + Rocket Growth 동기화
   - 하이브리드 옵션 분리 저장
   - HTTP 400 DEFAULT 재시도/2차 재시도
   - 로그 / Ctrl+C / 우클릭 복사

FIXES_v0.3.2_KR.txt (이전 기록 원문)
============================================================
Coupang Manager v0.3.2 패치

1. 아이템위너 기능 제거
- 공개 Open API에서 현재 아이템위너 여부를 신뢰성 있게 조회할 수 없어 UI/필터/수정/Excel 가져오기/CSV 내보내기에서 제거했습니다.
- 기존 사용자 DB의 오래된 item_winner 컬럼은 데이터 안전을 위해 물리적으로 DROP하지 않지만 앱에서는 사용하지 않습니다.

2. 배송방식 / 관리상태 / 판매상태 분리
- 기존 '상태' 값은 사용자가 Excel에서 관리해 온 값(판매중, 로켓그로스, 묶음, 묶임, 품절, 판매중지)을 보존하고 '관리상태'로 표시합니다.
- 별도 '배송' 필드를 추가하여 판매자배송 / 로켓그로스를 구분합니다.
- 별도 '판매상태' 필드를 추가하여 쿠팡 옵션 API의 실제 onSale 값을 저장합니다.
- 기존 DB에서 관리상태가 '로켓그로스'였던 행은 배송방식만 로켓그로스로 자동 파생하며 기존 관리상태를 바꾸지 않습니다.

3. 판매중지 판정 수정
- 등록상품 조회의 statusName(승인완료/승인반려/상품삭제 등)을 실제 옵션 판매상태로 사용하던 방식은 제거했습니다.
- vendorItemId별 상품 아이템 수량/가격/상태 조회 API를 사용합니다.
- onSale=false -> 판매중지
- 판매자배송: onSale=true + amountInStock<=0 -> 품절, 재고>0 -> 판매중
- 로켓그로스: onSale=false -> 판매중지, onSale=true -> 판매중
  (로켓그로스 품절은 로켓창고 재고 API를 별도로 연결해야 정확하므로 일반 상품의 amountInStock만으로 품절 처리하지 않습니다.)

4. 판매상태 갱신 기능
- 상품관리 화면에 '판매상태 갱신' 버튼을 추가했습니다.
- 전체 API 동기화가 끝난 뒤에도 옵션별 판매상태를 자동 갱신합니다.
- 확인시각과 API 재고수량을 DB에 저장하며 선택 옵션 상세에서 확인할 수 있습니다.
- 옵션별 조회 API 특성상 옵션 수가 많으면 기존 상품 동기화보다 시간이 더 걸릴 수 있습니다.
- 개별 옵션 조회가 실패하면 해당 행의 기존 관리상태는 건드리지 않고 로그에 오류를 남깁니다.

5. Excel 호환 유지
- 기존 쿠팡 관리.xlsm의 '상태' 열은 그대로 관리상태로 가져옵니다.
- 기존 로켓그로스 행은 배송방식 로켓그로스로 자동 인식합니다.
- 새 형식 Excel에 '배송방식', '관리상태', '판매상태' 열이 있으면 각각 직접 가져올 수 있습니다.
- 기존 상태/묶음/묶임 데이터는 마이그레이션 중 삭제하거나 변환하지 않습니다.

6. 기존 v0.3.1 기능 유지
- 상품보기 바로 열기
- 노출상품 ID 이력 조회/복사/상품 열기
- 다중 삭제
- Excel 가져오기
- 입고 이력표
- 상품조회 API 우선 + 미확인 노출ID fallback

주의
- 실제 쿠팡 계정 API 키가 이 개발 환경에 없으므로 라이브 계정의 판매상태 응답 자체는 여기서 호출하지 않았습니다.
- API 경로/응답 구조, DB 마이그레이션, 상태 변환, 하이브리드 병합, Excel 재가져오기, UI 실행은 로컬 테스트했습니다.

품절 = 주문가능 재고 0개. 주문가능 재고는 창고의 전체 물리적 재고와 다름

- 응답 누락 옵션은 '응답 없음', 실패 시 이전 값 유지 (0개로 덮어쓰지 않음)
